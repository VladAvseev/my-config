# my-config

Личная коллекция конфигураций приложений. Одна папка — одно приложение: рабочие файлы конфигурации
с оригинальными именами плюс `README.md` с описанием и пошаговой инструкцией от установки
до применения.

## Структура

| Папка | Приложение | Проверено на |
| --- | --- | --- |
| `terminal/` | foot + zsh | foot 1.28.0, zsh 5.9.2 |
| `opencode/` | OpenCode CLI | 2.2.0 |
| `vscode/` | Visual Studio Code | 1.143.1 |
| `_template/` | скелет для нового приложения | — |

## Конвенции

- Папка называется коротким именем приложения: `terminal`, `opencode`, `vscode`.
- Допускается объединять в одной папке приложения, которые настраиваются как одна связка:
  `terminal/` описывает эмулятор foot и шелл zsh. Вспомогательные файлы кладутся в подпапки
  (`themes/`).
- Файлы конфигурации лежат с оригинальными именами (`foot.ini`, `settings.json`), чтобы их можно было
  копировать в целевую директорию без переименования.
- В каждой папке обязателен `README.md` на русском. Разделы:
  1. Что настраивает.
  2. Требования: версия приложения, шрифты, плагины, расширения.
  3. Установка: универсальный Linux; отдельно Arch/Omarchy, если команды отличаются.
  4. Куда класть конфиг и как сохранить текущий (бэкап).
  5. Пошаговое применение.
  6. Проверка результата.
  7. Откат.
  8. Заметки и ограничения.
- Версия приложения, под которую проверен конфиг, указывается в README и в таблице выше.
- Новое приложение добавляется копированием `_template/` и заполнением README.
- Секреты (API-ключи, пароли, токены) в репозиторий не попадают. В конфигах — подстановка
  `{env:VAR}` (OpenCode) или явный плейсхолдер `<VAR>`, а в README — как задать переменную.

## Правила для агентов

- Репозиторий — источник истины для конфигов. Живые файлы в `~/.config` и `~/.vscode` не менять
  без отдельной просьбы: сначала правка здесь, затем применение по инструкции из README.
- Не копировать служебные и секретные файлы: `service.json`, `*.bak.*`, кеши, историю, токены.
- При изменении конфига обновлять соответствующий README: пути, версии, зависимости, шаги проверки.
- Команды установки сверять с актуальными пакетами; для Arch указывать `pacman` или AUR-пакет,
  если он есть.
- Не удалять и не переименовывать чужие папки и файлы без подтверждения.
- Репозиторий публичный: https://github.com/VladAvseev/my-config. Секреты и пути, привязанные
  к машине, в него не попадают.
- Коммитить только по просьбе владельца. Сообщение — на русском, в повелительном наклонении:
  «Добавить …», «Обновить …».

## Добавить новое приложение

1. Скопировать `_template/` в папку с коротким именем приложения.
2. Положить конфиг с оригинальным именем файла.
3. Заполнить `README.md` по разделам из конвенций.
4. Добавить строку в таблицу структуры выше.
5. Проверить, что в файлах нет секретов и путей, привязанных к конкретной машине, без пояснения.
